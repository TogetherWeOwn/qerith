# Synthetic archive/cache support

`mod support;` includes these adapters in a native integration test. They are
intentionally not a production crate or part of qerith-core's public domain API.
Fixture-local `Key { object, generation }` coordinates must be replaced by the
catalogue's authoritative types when composing product tests.

## Composition recipe

1. Create `FixtureC::new(key)`, a deterministic 3,072-byte opaque sequence with a
   SHA-256 digest. Its first 16 bytes distinguish fixture object/generation pairs
   so stale bytes cannot pass verification when relabelled with a newer key.
   Construction identity is private; `key()` returns a copy, not mutable access
   to the identity bound to the bytes and digest.
   These harmless arbitrary bytes **stand in for** committed ciphertext C;
   they are not generated by encryption and prove nothing about the approved
   format, OPRF, keys, plaintext authentication or E2EE.
2. Create a fresh `MemoryCache` and `Trace`; call `assert_empty` **before** doing
   the cold reconstruction. It checks staged, safety and delivery allocations,
   including other fixture generations. There is no filesystem cache or implicit
   warm fallback. A separate negative test deliberately retains safety bytes and
   verifies that cold precondition fails.
3. Spawn `Archive` with `MockBackbone` and a `Fault`. The archive owns only an
   ephemeral loopback `velmora-test-nntp` server. Every part is encoded by the
   pinned engine's `yenc::encode_segment`, retrieved by `NntpClient::article_to`,
   decoded by `yenc::decode_part_to`, and checked for contiguous placement and
   whole-file length/digest/exact-byte equality before publication.
4. Call `reconstruct` with the expected fixture and attempt fault. Configuration
   faults (`Missing`, `Lost`, `Corrupt`, `Disconnect`, `Unavailable`, `Timeout`)
   are chosen at `spawn`; `PartialStagedWrite` and `CancelAfter` operate at the
   staged-write boundary during `reconstruct`. Use the same fault at both calls
   for the standard scenarios. The timeout case has 60 s server latency and a
   50 ms ARTICLE deadline, starting after connection/authentication; every attempt
   retains a 10 s outer bound and 2 s per transport operation. A delayed archive is explicitly **one-shot**: completing
   `reconstruct` shuts down that server and its delayed sessions. Another call
   returns `Unavailable` until `archive.reset(fault).await` creates a fresh server.
   This avoids accumulating authenticated slots: the pinned server's ARTICLE
   delay observes shutdown, but not client disconnect. Reset drops the old spool
   (including re-POST state); it does not change the fixture identity or cache.
   To retry, reset the archive and separately restart the staged cache allocation.
   These are synthetic guardrails, not service budgets.
5. Assert `delivery(key)` and use `Trace::assert_replay` for stable event order,
   exact key, length and digest. Random ports and wall clocks do not enter traces.
   Failed attempts record a typed failure; no new delivery is published. Existing
   independently verified delivery is retained. Staged prefixes remain invisible.
6. `restart(key)` discards that attempt's staged bytes. The next attempt fetches
   from the archive again; it does not resume from a hidden warm prefix. This is
   an in-memory reference of restart semantics, **not process/durable recovery**.
   `CancelAfter` injects an explicit cancellation result at a completed-write
   boundary; it does not qualify dropping a pending later ARTICLE future with an
   existing staged prefix. The timeout case drops a pending retrieval before a
   prefix is staged. In-flight cancellation after partial progress remains an
   integration qualification case, not a passing claim of these helpers.
7. `cleanup(key)` deletes only the fixture's staged/safety/delivery allocations;
   other keys remain. `shutdown` or dropping the archive signals upstream session
   teardown and aborts the owned listener. The teardown test observes EOF on an
   already-open fixture connection. No daemon, disk path or recurring job exists.

The cache exposes only explicit staging, verified publication, safety retention,
read, restart and fixture cleanup operations. It selects no database or object
service, grants no logical delivery lease and implements no ingest/restore job,
S3 endpoint, authorization, scheduling or eviction policy.

## Deterministic scenarios and limits

| Control | Evidence / interpretation |
| --- | --- |
| `Healthy` | Full three-part ARTICLE/yEnc reconstruction; replayed trace, bytes, SHA-256 and generation |
| `Missing(n)` | Article omitted from fixture corpus; engine returns not-found |
| `Lost(n)` | Stored article hidden through upstream fixture's missing-ID mechanism |
| `Corrupt(n)` | Encoded payload altered with original checksum retained; engine integrity refusal |
| `Disconnect(n)` | Upstream mid-article disconnect; no delivery publication |
| `PartialStagedWrite` | Half a decoded segment written to staged cache, then explicit write failure |
| `Unavailable` | No fixture archive allocation; explicit unavailability with no safety fallback |
| `Timeout` | Attempt future dropped before delayed ARTICLE completes; staged bytes cannot publish |
| `CancelAfter(n)` | Deterministic cancellation at the nth completed staged segment, then explicit restart |
| `repost_from_retained` | Existing engine POST mechanism restores missing/hidden article using a separately verified intact retained C; never reported as cold-only or PAR2 repair |
| `repair_without_retained_source` | **Not qualified**: portable PAR2/archive repair remains owned by velmora; current qerith re-exports no such adapter. No parity algorithm or repair implementation is added here |

The repost helper validates the supplied retained bytes against the exact fixture
before using its corresponding encoded article. It is not an implicit repair
fallback. Corrupt visible articles, absent parity, recovery capacity and repair
without an intact retained source are not qualified by this helper.

`Reconstruction` evidence is created only by full retrieval. `mock_pair_matches`
checks exact generation/length/digest and distinct nonempty **mock provenance**,
not reseller labels. The negative case uses two labels with the same provenance.
Separate fixture servers and provenance strings prove neither independent live
backbones nor authenticated plaintext readability or lawful live R2 eviction.
These helpers cannot authorize deleting a real safety copy.

## Verification and dependencies

`synthetic_archive.rs` exercises the recipe, faults, repair limits, restart,
publication integrity, provenance negatives and ownership-scoped teardown through
the existing workspace test job in GitHub Actions. Full suites are not run on the
shared host. No live NNTP provider, credential, customer data or production
resource is needed. The existing immutable velmora pin is unchanged.

Only `sha2 = 0.11.1`, already present in the locked engine graph, is added as a
direct dev dependency. Its locked checksum is
`47d7069beb7d6ac7b9acd1039986e73443f24234f41074da099d6f994ac9ad19`;
its manifest specifies `build = false` and no procedural macro target. There are
no new package versions or transitive packages. Cargo has no stable native
release-age filter or blanket build.rs/proc-macro refusal; `--locked` is only
resolution control, not either protection. The existing locked crypto/native
build graph is retained, not newly exempted. Clean-runner install/build and
full verification use the existing Actions gates; no local install/build or
supply-chain pilot acceptance is claimed.

REA angle: reuse the pinned engine's encoder/decoder/client and delivered
synthetic server's corpus, spool, fault and shutdown behavior. No NNTP, yEnc,
cryptography, PAR2, scheduler or third-party implementation is copied here.
