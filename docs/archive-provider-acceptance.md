# Experimental product-consumer source acceptance

This matrix defines the finite scope of the default-off `archive-provider` source
milestone. It does **not** declare complete NNTP/S3 product support. The full
product objective remains: both archive backends beneath the product services,
with common R2 staging/cache/delivery, durable recovery, authenticated qualification,
bounded global lifecycle and public sharing. Those runtime obligations remain
outside this source package; they are not satisfied by the generated tests below.

## Deferred or unsupported product boundaries

These remain full-product obligations after the experimental source milestone;
none is an implicit acceptance criterion already satisfied by the table above.

| Boundary | Required next evidence / implementation |
| --- | --- |
| Durable catalogue/outbox/archive journal | Real atomic transitions, fencing, persisted immutable identity and crash/restart recovery; no database is selected by this source milestone. |
| Runtime/cache/queue/control integration | Product runtime adapters and physical request/socket/pool settlement; dropping a future is not absence or lease-release proof. |
| Authenticated archive qualification | Actual two-independent-backbone NNTP qualification and a distinct S3 durability/readability assessor, preserving crypto verification requirements. |
| Safe S3 network transport | Reviewed signing/HTTP implementation beneath the canonical shared seam, without automatic paid failover. |
| New-provider upload-to-cold recovery | Coherent state and real disposable/simulated-primary-unavailable retrieval receipts for both backends without prohibited safety-copy eviction. Warm retained bytes do not satisfy this. |
| Global common-R2 lifecycle | Global admission, retention, cleanup, eviction and invalidation for both backends, beyond attempt-local generated tests. |
| Public sharing and full protocol parity | Actual public-link creation/revocation, isolation and immutable-version delivery; a complete native/REST/MCP/S3 operation matrix with protocol-appropriate outcomes. Compatible Copy/aliases are not public sharing. |

The full programme retains accountability for these boundaries and its technical
producer selection. This document neither commissions a duplicate archive engine
nor authorizes a provider switch, credential, purchase, migration or deletion.
